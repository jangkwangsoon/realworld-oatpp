## 목표

AI(Claude 등)가 realworld-oatpp 코드를 자유롭게 수정/추가할 수 있도록, 자동화된 테스트와 CI 파이프라인으로 구성된 안전망을 구축한다. 모든 API 엔드포인트에 대한 테스트 커버리지, GitHub Actions CI, 그리고 전체 문서화(CLAUDE.md, README, API 문서, 아키텍처 문서)를 완성한다.

---

## 제약 사항

- **리팩터링 없음**: 기존 코드 구조(헤더 전용, 인증 반복 등)를 변경하지 않음
- **CI 플랫폼**: GitHub Actions
- **테스트 범위**: 단위 테스트 + 통합 테스트 (PostgreSQL 서비스 컨테이너 사용)
- **E2E 테스트 제외**: 전체 HTTP 흐름 E2E는 범위 밖
- **단계적 실행**: CI → 테스트 → 문서 순서로 진행
- **빌드 시스템**: 기존 CMake 유지, 테스트 타겟 활성화
- **C++ 표준**: C++11 (기존 유지)

## 수용 기준

### Phase 1: CI 파이프라인
- GitHub Actions 워크플로우 파일 (`.github/workflows/ci.yml`) 생성
- PR 및 main 브랜치 push 시 자동 빌드 트리거
- oatpp 모듈 (oatpp, oatpp-zlib, oatpp-postgresql) 빌드 및 캐싱
- PostgreSQL 서비스 컨테이너 설정
- CMake 빌드 성공 확인
- 테스트 실행 및 결과 리포트

### Phase 2: 테스트
- CMakeLists.txt에서 테스트 타겟 활성화
- 테스트 프레임워크 설정 (oatpp::test::UnitTest 기반)
- UserController 테스트: 로그인, 회원가입, 사용자 조회/수정, 프로필, 팔로우/언팔로우
- ArticleController 테스트: CRUD, 목록 조회, 피드, 즐겨찾기, 태그 목록
- CommentController 테스트: 생성, 목록 조회, 삭제
- 인증 유틸리티 테스트: JWT 토큰 생성/파싱, 만료 처리
- 통합 테스트: 실제 PostgreSQL 연동 CRUD 동작 검증
- CI에서 모든 테스트 통과

### Phase 3: 문서화
- CLAUDE.md 생성: 프로젝트 규칙, 구조, 빌드 방법, 테스트 방법
- README.md 현대화: 배지, 빠른 시작, API 개요
- API 문서: 전체 엔드포인트 목록, 요청/응답 형식
- 아키텍처 문서: 계층 구조, 의존성 주입, 데이터 흐름

## 노출된 가정과 해결

| 가정 | 도전 | 해결 |
|------|------|------|
| 리팩터링이 테스트 전에 필요하다 | 현재 구조에서도 테스트 가능한가? | oatpp 가상 네트워킹으로 헤더 전용 코드도 테스트 가능. 리팩터링 없이 진행 |
| E2E가 필요하다 | 단위+통합으로 충분한가? | C++ E2E 설정 비용 대비 단위+통합이 AI 안전망으로 충분 |
| 한 번에 모두 완성해야 한다 | 단계적 접근이 가능한가? | CI→테스트→문서 순서로 단계적 진행이 효율적 |
| CI에서 PostgreSQL이 어렵다 | GitHub Actions에서 가능한가? | 서비스 컨테이너로 쉽게 PostgreSQL 실행 가능 |

## 기술 맥락 (브라운필드)

### 핵심 기술 스택
- **oatpp 1.3.0**: 비동기 HTTP 서버 프레임워크
- **oatpp-postgresql 1.3.0**: PostgreSQL ORM
- **oatpp-zlib 1.3.0**: 응답 압축
- **cpp-jwt**: JWT HS256 인증
- **libbcrypt**: 비밀번호 해싱 (cost 12)
- **CMake 3.1+**, **C++11**

### API 엔드포인트 (20개)
- **사용자 (8개):** 로그인, 회원가입, 사용자 조회/수정, 전체 사용자, 프로필, 팔로우/언팔로우
- **게시글 (9개):** 생성/수정/삭제, 목록(태그/저자/즐겨찾기), 피드, 조회, 태그, 즐겨찾기
- **댓글 (3개):** 목록, 생성, 삭제

### 데이터베이스 (5개 테이블)
users, articles, favorites, follows, comments

### 핵심 엔티티

| 엔티티 | 필드 | 관계 |
|--------|------|------|
| User | id, username, email, bio, image, hash | 여러 Article, Comment 소유; User 팔로우 |
| Article | id, slug, title, description, body, tag_list[], favorites_count | User(저자) 소속; 여러 Comment 소유; User가 즐겨찾기 |
| Comment | id, body, created_at, updated_at | Article 소속; User(저자) 소속 |
| Favorite | user_id, article_id | 연결 테이블: User ↔ Article |
| Follow | follower_id, followed_id | 연결 테이블: User ↔ User |
